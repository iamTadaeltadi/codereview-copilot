# Limitations and threats to validity

**The defects are generated, and the generator conditions on what it later evaluates.** A task exists only when the caller's syntax tree demonstrates the dependency the mutation breaks. That makes the evidence exact, and it also means every defect is one for which a two-file evidence set exists by construction. Real cross-file defects frequently arrive through channels a static call graph does not represent: dynamic dispatch, event listeners, dependency injection, framework lifecycle hooks, reflection, schema mismatches, configuration. Nothing here speaks to those. The 96 mined regression candidates we release are the external check we have not yet run.

**Most generated defects are not verified by the repositories' own tests.** Section 4.4 reports the funnel: of 86 attempted, 17 are test-verified, 28 are not caught by the selected tests, and 41 could not be run to a verdict. A fifth of those attempted, and 38% of those with a verdict, is lower than we would like. It says the syntax-tree verifier accepts many mutations whose breakage no existing test observes; it does not say those mutations are harmless. The third version's defects were being run through the same check at the time of writing. [[TESTVERIFY-V3-LIMIT]]

**The ceiling is measured on one model.** The diff-only rate is reported for gpt-4o-mini on every version. The second version's runs, withdrawn, put llama-3.3-70b and deepseek-v3.2 at the same ceiling, so we do not expect a cheaper model to lower it, but on the third version it is one model.

**The precision signal comes from a stopped run.** The third version's base run was halted at 201 of 277 defects because the diff-only rate exceeded the pre-set threshold, and the rule said to report only the ceiling. We report one more number from it, the precision comparison in 4.7, because it is judge-free and because the twins measure the same thing directly; it is one model, one serialisation and 200 paired defects, it was not pre-registered on this version, and a reader should weigh it as a signal that the twins either confirm or do not.

**Python only.** The generator, the import resolution and the verifiers are written against Python's `ast`. The project's graph builder parses four languages; the benchmark exercises one.

**The pools are samples.** Each repository contributes up to three hundred production files chosen at random, not the whole repository, so a caller that exists in the repository may be absent from the pool and a function that is called in many places may be represented by one. Twin safety is checked against the pool, so a caller outside the sampled files could depend on a change the pool calls safe. Yield per repository varies from one to eight for this reason.

**The reviewer prompt presumes a defect.** One sentence in the system prompt tells the model that humans found real problems in the diff and to assume there is something to find. It is identical across arms, so no comparison between arms is confounded by it, but every absolute rate is: the twin clear rates are a floor, and the diff-only ceiling is that of a model told to flag. The neutral-prompt variant that measures the size of this effect is implemented and has not run.

**The twins may be unfair to a prudent reviewer.** The mutated functions are public. A twin is safe for every caller in the pool, and a change to a public default or exception type can still break code outside the repository; a reviewer that flags it anyway is applying a sound rule. Twins built on private functions, where the pool is the whole truth, would settle it and are the right next construction. Twins exist for two of the five mutation kinds, most of them default flips, and on gpt-4o-mini the clear rate is at a floor where no arm comparison can be read.

**The retrieval conditions start from the fault location, and the graph condition carried a span.** Every retrieval condition seeds its query from the function covering the ground-truth line, which a reviewer would not know; the comparison between conditions is fair because all share the seed, but the absolute rates are those of retrieval that starts in the right place. The graph condition alone also received the seed's line range and metadata; Section 4.5 reports the stripped control that measures what that hint was worth. [[BS-LIMIT]]

**The real-defect retrieval result is one model and one run per condition.** A random-other-files control separates retrieval through the graph from retrieval from other files, and the graph wins by fifteen points; but the five conditions were each run once, on the same day with the same pipeline, and the diff-only rate matches the August run on the same defects. A second model and a second seed would strengthen it.

**Statistical power.** Pairing across arms and the McNemar test give the design its power; the repository-clustered interval is wider than the task-clustered one because tasks within a repository share files. A null with an interval of several points in either direction is a bound, not a demonstration of equivalence.

**Scope of the agent result.** The search-trigger measurement is on a bare model with two tools and no harness. Harnessed products explore unprompted [arXiv:2607.16740]; the result says nothing about them.

**The history of this study.** Seven claims were made and withdrawn during this work, each on the project's own evidence, and this paragraph is the only place the list appears: that benchmarks cannot contain cross-file defects; that a fault-location oracle was an evidence oracle; that random context beat graph retrieval; that retrieval relevance was undetectable; that the retrievers were comparable in what they retrieved; that the first generated benchmark measured what it claimed; and that the second did. The first generated benchmark's distractors did not parse in 145 of 204 tasks, its evidence demonstrated the dependency in roughly a third of tasks, and its diff-only arm found the defect line 93% of the time. The second's labels carried the mutated line's number, its resolver accepted a same-name import from any module in 36 of 229 tasks, 25 of its 150 twins had a dependent call in a shown file, 91 of its 650 distractors changed the syntax tree, and an unparseable reply was scored as correctly silent; an external review on 26 October 2026 found these, and `results/WITHDRAWN-v2-structure.md` records them. Every number from both is withdrawn and the files are kept with a notice. The third benchmark was generated after those faults were found, with a test for each, and its diff-only rate is the result of this paper.
