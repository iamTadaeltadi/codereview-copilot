# Discussion

**What the diagnostics say about benchmarks.** A benchmark can be carefully built and still be unable to measure context. Three versions of ours, the last with every known leak closed and audited, give the diff alone 93%, 97.8% and 95.5% of the defect lines. A study of interprocedural context for vulnerability detection reports that adding callers and callees does not raise accuracy for the models it tests, and lowers it for several [arXiv:2604.08417], and ContextCRBench finds that added code lowers line-level localisation [arXiv:2511.07017]. None of these benchmarks is wrong about what it contains; each is silent about context because the diff already answers the question. The partial-input baseline is a one-line check, and the lesson of the third version is that it has to be run on the repaired instrument, not assumed to improve with the repairs.

**Why the ceiling survived the repair.** The second version leaked in five identifiable ways, and closing them moved the ceiling by two points. What remains is not a leak. The model flags 2.7 of the 4 changed lines per task; it does not pick the defect out, it declines to leave much out, and a semantic edit among cosmetic ones is always in the set. Two things follow. A mutation benchmark that wants detection to carry information needs distractors that are themselves semantic and plausible, several changed lines any of which could be the defect, or more than one defect per diff; cosmetic distractors test whether the model can spot the one edit that does something, and it can. And the metric that still moves on such a benchmark is precision, whether the model also flags the harmless lines, which is a property of restraint rather than of understanding. We did not run the arms on the third version to measure it, because the pre-set rule did not allow a partial run to become a result.

**Three questions, and what happened to each.** The held-constant experiment was built to answer three questions the real-defect result cannot, because real pull requests cannot be controlled: whether the model understands the defect or only points at its line; whether context causes false alarms; and whether it is the caller's code or the description of the link that helps. The first needed the model judges, and nothing from them is reported, so it is not measured. The second is partly answered by the stopped run, where the real caller lowers precision by fourteen points and foreign code does not, and directly by the twins in 4.3. The third cannot be answered on a benchmark where the diff alone finds the line 95% of the time, and both attempts are withdrawn; the one precision comparison that survives, bare link against scrambled control, is zero. What the experiment answered instead is a question it was not designed for: whether a planted-defect benchmark can measure context at all. Two of the three questions are open, and the next step is a benchmark on which the diff alone cannot find the defect.

**Where context can be measured.** The real defects are the set with headroom, and on them a retrieval result holds: a small selection that reaches the depended-on caller localises 48% against 33 to 36% for the diff alone, for random code from other files and for lexical retrieval at the same budget. Both random-code controls sit on the diff-only rate, so the gain is from reaching the caller, not from more tokens. The anchor-versus-evidence measurement says why there is room: a third to a half of the reference comments justify themselves with code the diff does not show. This is one model and one run per condition, and it is a result about selection; whether describing the relationship helps once the caller is reached is the question the withdrawn experiment was built for, and it is open.

**Why this does not contradict SWE-PRBench and AACR-Bench.** SWE-PRBench reports that eight frontier models get worse as same-file context is appended to the diff, and AACR-Bench reports that moving from diff to file to repository granularity changes performance in a direction that depends on model and language [arXiv:2603.26130, arXiv:2601.19494]. Both vary the *amount* of context. We hold the amount fixed at 1,500 tokens and vary the *selection*, and our own data reproduce their null first: whole changed files localise 36% against 33% for the diff, and random nodes from other files 33.5%. What moves the number is a small selection that reaches the depended-on caller. "More context does not help" and "the right context helps" are one finding seen from two sides: tokens of the wrong kind dilute, and a few tokens of the dependent kind inform. The two benchmarks could not separate the two because, in a file or a repository window, the dependent code arrives mixed with everything around it. The comparison has limits: their models are at the frontier and ours are not, and they score whole pull requests where we score located defects.

**The twins.** [[TWINS-DISCUSSION]]

**What a generated benchmark owes its reader.** Two numbers that a mutation benchmark can always report and that ours did not report at first: the diff-only rate, and the fraction of defects an existing test catches. The second is 38% of those we could run, which says the syntax-tree verifier accepts many mutations the repository's own tests would not notice. Those mutations are not harmless, but a reader is entitled to know that most of the benchmark's ground truth is verified by static reasoning rather than by execution, and a benchmark that cannot be installed for a quarter of its repositories should say that too.

**What this does not show.** Nothing here speaks to dependencies a static call graph cannot express, to languages other than Python, to models at the frontier, or to tool-using agents, which explore unprompted and for which the search-trigger result does not apply. Nothing here says whether dependency metadata helps a model that has the caller in front of it; the experiment that would say so has not been run on a benchmark that could carry it.

**What the record shows.** Seven claims were made and withdrawn during this work, each on the project's own evidence, and Section 6 lists them. The last two are the held-constant experiment on each generated benchmark. The design was pre-registered, the controls were matched, the judges were validated and the analysis resampled repositories; none of that protected it from an instrument that gave the answer away. The diagnostics in this paper are what we would run first next time, and they are cheap enough that anyone can.
