# Discussion

**What the diagnostics say about benchmarks.** A benchmark can be carefully built and still be unable to measure context. Three versions of ours, the last with every known leak closed and audited, give the diff alone 93%, 97.8% and 95.5% of the defect lines under a prompt that presumes a defect, and 30% under one that does not. A study of interprocedural context for vulnerability detection reports that adding callers and callees does not raise accuracy for the models it tests, and lowers it for several [arXiv:2604.08417], and ContextCRBench finds that added code lowers line-level localisation [arXiv:2511.07017]. None of these benchmarks is wrong about what it contains; each is silent about context because the diff already answers the question. The partial-input baseline is a one-line check, and the lesson of the third version is that it has to be run on the repaired instrument, not assumed to improve with the repairs. The lesson of the real defects is that it has to be read against a chance baseline too: on the raw diff every condition's 36% was the rate of random line placement, and the harness, not the model, had set it.

**Why the ceiling survived the repair.** The second version leaked in five identifiable ways, and closing them moved the ceiling by two points. What remains is not a leak. The model flags 2.7 of the 4 changed lines per task; it does not pick the defect out, it declines to leave much out, and a semantic edit among cosmetic ones is always in the set. Two things follow. A mutation benchmark that wants detection to carry information needs distractors that are themselves semantic and plausible, several changed lines any of which could be the defect, or more than one defect per diff; cosmetic distractors test whether the model can spot the one edit that does something, and it can. And the metric that still moves on such a benchmark is precision, whether the model also flags the harmless lines, which is a property of restraint rather than of understanding. We did not run the arms on the third version to measure it, because the pre-set rule did not allow a partial run to become a result. The neutral-prompt run in 4.3 adds a third thing: the ceiling is also the prompt. Told that the diff has a defect, the model names the semantic edit 95% of the time; allowed to say nothing, it names it 30% of the time, and the arms then separate, but by flagging rather than by discriminating, since every gain on the defects is matched by a loss on the twins and balanced accuracy does not move.

**Three questions, and what happened to each.** The held-constant experiment was built to answer three questions the real-defect result cannot, because real pull requests cannot be controlled: whether the model understands the defect or only points at its line; whether context causes false alarms; and whether it is the caller's code or the description of the link that helps. The first needed the model judges, and nothing from them is reported, so it is not measured. The second is answered by the twins under a neutral prompt: the caller that shows a change to be safe costs 27 points of restraint on gpt-4o-mini and 2 on deepseek-v3.2, and each statement about the dependency costs more, down to one in nine on the first model and four in five on the second with the relation named. The third cannot be answered for detection on a benchmark where the diff alone finds the line 95% of the time under the presuming prompt, and both attempts are withdrawn; under the neutral prompt the code and the description are separable and both move the model, the code by 22 points of detection and 27 of restraint, the bare link by 11 more and 15 more, and the balanced accuracy of every arm that carries evidence is within noise of, or below, the diff alone. What moves is the willingness to flag, on defects and safe changes alike. What the experiment answered instead is a question it was not designed for: whether a planted-defect benchmark can measure context at all. Two of the three questions are open, and the next step is a benchmark on which the diff alone cannot find the defect.

**Where context can be measured, and what was found there.** The real defects are the set with headroom, and on them this project made four runs. The first reported a retrieval result it now withdraws: graph retrieval appeared to localise 48% against 33 to 36% for every control, and the gain was a line span the graph condition alone had been given. The second, with the retrieval repaired, put every condition at the rate of random line placement, and the check that showed why, fewer than one quoted line in ten reported on the line that holds it, is one any benchmark that scores by line should run: a raw unified diff asks the model to count from hunk headers, and the harness, not the model, had set a ceiling of 36%. With the lines numbered, every condition sits at about half and fifteen points above chance, and on the full defect set nothing separates graph retrieval from random code of the same size, in two runs. The anchor-versus-evidence measurement says why there is room: a third to a half of the reference comments justify themselves with code the diff does not show. On exactly those defects, the pre-registered subset of the final run, the callers-first walk is twelve points above random code from other files and above the diff alone, with an interval that excludes zero; it was chosen with earlier readings of +3 and −2 in view, it is eight defects on one model, and we call it a lead. Two readings of the full-set null stay open: that the model cannot use a caller it is handed, which the twins under the neutral prompt make plausible, since there the caller is read as an accusation rather than as evidence; or that for most real defects the justification is not where a 3,000-token neighbourhood of the changed functions looks. The subset lead favours the second reading, and a second model would decide it.

**How this sits with SWE-PRBench and AACR-Bench.** SWE-PRBench reports that eight frontier models get worse as same-file context is appended to the diff, and AACR-Bench reports that moving from diff to file to repository granularity changes performance in a direction that depends on model and language [arXiv:2603.26130, arXiv:2601.19494]. Both vary the *amount* of context. We hold the amount fixed at 3,000 tokens and vary the *selection*, and on the full defect set our data reproduce their null: with the diff lines numbered, the diff alone localises 50.8%, random code from other files 52.9%, lexical retrieval 52.9% and the callers-first graph walk 54.1%, and no difference excludes zero. On real defects, for this model and budget, no selection method we tried moves the number on all defects, which is their finding restated with the selection controlled; the one movement is on the 64 defects whose reference comment cites code outside the diff, and it is a lead. The twins add the part their designs cannot see: when the dependent code is handed to the model on a safe change, it raises false alarms, and a statement of the dependency raises them further. The comparison has limits: their models are at the frontier and ours are not, and they score whole pull requests where we score located defects.

**The twins.** Under the presuming prompt no arm on either model clears more than 11% of the changes every sampled caller tolerates, and on gpt-4o-mini none clears more than 4%; under a neutral prompt the same model clears 82% from the diff and 11% once the relation is named, and deepseek-v3.2 goes from 89% to 79% in the same order, so the prompt had hidden an effect whose direction both models share and whose size is the model's. The design's largest judge-free finding is that structure stated in the prompt drives flagging: on the twins it drives false alarms, on the defects it drives detection by the same steps, and balanced accuracy over the two is 56% for the diff alone, no better for the caller or the bare link, and ten points worse for the attributed link. Foreign code of the same length does none of this. Under the plain prompt the extra flagging is partly defensible, since the prompt presumes a defect and the function is public; under the neutral prompt it is not, and it is the direction a context method has to reverse before it can claim to help a reviewer rather than to help a detector. A wrong link costs as much as a right one on gpt-4o-mini, on the twins and on the defects, so the model is not reading the relation and finding it violated; it is reading that a relation exists and treating that as the defect. The discrimination task is where a context method would have to show its value, and the benchmark now contains it with twins that are safe across every sampled file, under both prompts. The signal-detection reading of 4.3 says the same in two numbers: d′ never rises above the diff's 0.37 in any arm that carries evidence, and c falls from +0.71 to −1.07. This is the pattern that "Words Speak Louder Than Code" [arXiv:2606.30587] reports for vulnerability detection, where context that leaves the code unchanged, an author's name, a framing, a prior verdict, moves eight models' verdicts from safe to vulnerable without the model identifying a vulnerability. Structural dependency context behaves as one more such cue in code review: the caller and the stated relation are read as reasons to flag, on defect and safe change alike.

**What a generated benchmark owes its reader.** Two numbers that a mutation benchmark can always report and that ours did not report at first: the diff-only rate, and the fraction of defects an existing test catches. The second is 38% of those we could run, which says the syntax-tree verifier accepts many mutations the repository's own tests would not notice. Those mutations are not harmless, but a reader is entitled to know that most of the benchmark's ground truth is verified by static reasoning rather than by execution, and a benchmark that cannot be installed for a quarter of its repositories should say that too.

**What this does not show.** Nothing here speaks to dependencies a static call graph cannot express, to languages other than Python, to models at the frontier, or to tool-using agents, which explore unprompted and for which the search-trigger result does not apply. Nothing here says whether dependency metadata can help a model find a defect without also making it flag safe changes; on the one benchmark and model where both were measured under the same prompt, the two rose together and balanced accuracy did not. What it says is that on a safe change the metadata hurts, that on generated defects it raises detection only as far as it raises false alarms, and that on real defects no retrieval tried here helps.

**What the record shows.** Eight claims were made and withdrawn during this work, each on the project's own evidence, and Section 6 lists them. The last three are the held-constant experiment on each generated benchmark and the retrieval result on real defects. The design was pre-registered, the controls were matched, the judges were validated and the analysis resampled repositories; none of that protected it from an instrument that gave the answer away, twice on generated defects and once on real ones, each time through a line number or a line span that only one condition received. The diagnostics in this paper are what we would run first next time, and the control that withdrew the last claim cost less than a dollar and an afternoon.
