# Can this benchmark measure context? Diagnostics for context-dependent code review

## Abstract

Systems that give a language model more of the repository during code review change which code the model sees and how its relationships are described, at once. We first ask whether a review benchmark can measure context at all, with three tests known elsewhere and rarely run here. A partial-input baseline: given only the diff, a model finds the defect line in 97.8% of tasks on a mutation benchmark with verified cross-file evidence. An anchor-versus-evidence measurement on 291 test-verified real defects: every comment anchors inside the changed files, yet 33 to 50% rely on code outside the diff. And a contrast set of safe twins, the same mutation placed where the shown caller is verifiably robust: no arm on either of two models clears more than about a fifth of them.

We then hold the evidence fixed and vary only the dependency metadata between snippets, across three model families and two serialisations, with scrambled, foreign-code and header-only controls, a comprehension probe and two judges from different families. The real caller raises caller-grounded explanation by 8 to 12 points over foreign code under the independent judge; the header alone adds nothing. A bare true link adds 7 to 12 points on two families under one serialisation only, and raises precision, which needs no judge, by 10 to 14 points on all four runs; the pre-registered keyword rubric, found invalid before the full data, spans zero. On 219 real defects, graph retrieval repaired to reach the caller localises 48% against 33 to 36% for the diff alone and for random, random-other-file or lexical retrieval at the same budget. Generator, benchmark, runs, judges, analysis and the record of withdrawn claims are released.
