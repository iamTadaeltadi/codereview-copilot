# Introduction

A pull request changes one function. Three files away, another function relies on the behaviour that just changed. Nothing in the diff is wrong on its own terms, and a reviewer who reads only the diff cannot see the problem. Systems that give a language model more of the repository exist to close this gap, and the most elaborate of them build a dependency graph, retrieve the neighbourhood of the change, and present it to the model with its structure attached.

Two things change at once in that design. The model receives different code than it would from a plain lexical search, and it receives a statement of how the pieces relate. Published comparisons report the combined effect [arXiv:2509.05980, arXiv:2601.19494]. They do not say which part is doing the work, because in an end-to-end comparison the retrieved set and its representation move together. We set out to separate them with a held-constant-evidence design: the same diff and the same snippets in every arm, and only the metadata that describes their relationships varied, from absent through scrambled, a bare link, a typed relation and a wrong pointer.

This paper reports what had to be true of the benchmark before that experiment could mean anything, and the finding that it was not. The partial-input problem is known from natural language inference [arXiv:1803.02324, arXiv:1805.01042, arXiv:1905.05778]: if one part of the input already determines the answer, an experiment on the other part measures nothing. For code review the one-line version is to give the model the diff alone and see how often it finds the defect. On every generated benchmark we built it almost always did. The first version leaked through broken distractors and loose evidence; the second through line numbers in its labels, a resolver that accepted any same-name import, distractors that changed the syntax tree, and a defect that sat last in the diff six times in ten. An external review found those, we closed each one with a test, regenerated the benchmark from the same repositories, and the diff alone still found the defect line in 95.5% of tasks, because the model flags most changed lines and the one semantic change is always among them. That is the result of this paper: a benchmark can pass every construction check and still be unable to measure context, and the check that tells you is cheap enough to run first.

Three further diagnostics say where context could be measured and what else a benchmark needs. On 291 test-verified defects from a mined review benchmark [arXiv:2603.23448], every reference comment anchors on a file the pull request changed, and a third to a half of them refer to code the diff does not contain, so where a comment sits is not where its justification lives; on those defects the diff alone localises a third, which leaves room. A contrast set [arXiv:2004.02709, arXiv:1909.12434] of safe twins, the same mutation placed where every caller in the repository tolerates it, measures whether any context makes a model say a change is safe; under a neutral prompt it shows the opposite, that the caller which proves the change safe, and every statement about the dependency on top of it, makes the model flag it. And running each generated defect against its repository's own test suite says how many a test would have caught: a fifth of those that could be run.

On the one set with headroom we report a retrieval result. Retrieval that reaches the depended-on caller through the dependency graph localises 48% of the real defects against 33 to 36% for the diff alone and for random or lexical retrieval at the same budget. It is one model and one run per condition, and it is a result about reaching the caller, not about describing the relationship once reached. A search-trigger test on a bare tool-equipped model closes the frame: asked to review a diff it searched in none of forty tasks; told the defect depended on another file, it searched in all forty.

The contributions are the four diagnostics with their results, the generated benchmark with the generator, the audit and the twins that an experiment on context would need, the retrieval result on real defects, and the record: seven claims made and withdrawn on the project's own evidence, the last two being the held-constant experiment itself. Each measurement is stated with what it does and does not support.
